# Punctuation trivia

Load this file when the draft still uses model punctuation. Em dashes and
ranges already live in the checkable set (`SKILL.md`).

## Colons

A colon introduces a list. A colon is also fine as a short label in an update,
brief, status note, or PR ("Summary:", "Changes:", "Remaining work:"). Do not
use a colon to glue two clauses in ordinary prose.

Before: Read for the schema: the feature fires.
After: Read for the schema. The feature fires.

## Straight quotes

Use straight quotes, not curly quotes.

Before: The system logs each “event” as it happens.
After: The system logs each "event" as it happens.

## Middle dots

Use a comma, "and", or separate lines. Do not use the middle dot (·) as a
separator.

## Em dash reminder

Join clauses with a period or "and". Write ranges with "to".

Before: The build is fast — it finishes in 10 to 20 seconds.
After: The build is fast. It finishes in 10 to 20 seconds.
